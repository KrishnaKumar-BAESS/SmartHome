# UI audit — HOUSE.SYS web application

Audit date: 2026-09-12. Branch `codex/modernize-smarthome` at commit `ee6e477`.

**Start with the [follow-up audit](ui-audit-follow-up.md)** for 41 additional
findings, 8 optional improvements, wider workflow/viewport checks, and
[corrections to this initial audit](ui-audit-follow-up.md#corrections-to-the-original-audit).
The initial observations below are retained for traceability; the follow-up
supersedes inaccurate claims, including L-08, A-16, the unrendered slider,
reduced-motion behavior, and panel-isolation visibility.

This is a findings log, not a roadmap. Each item records what is lacking today,
where the behaviour lives in source, and what addressing it would take. Nothing
here is fixed by the audit itself; remove or update an entry in the same change
that resolves it, and keep the [known limitations](../../docs/limitations.md)
table consistent.

## Method and scope

| Aspect       | What was done                                                                                                                                             |
| ------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Source       | Full read of `home-docs/apps/web/src/` (controller, renderer, all view components, `styles.css`, `index.html`, Vite/Playwright config)                    |
| Browser      | Chromium via the local Vite dev server at 1440×900 (desktop) and 375×812 (iPhone-class emulation); all eight modes, search, overlays, both themes         |
| Automation   | axe-core 4.10.2 injected in-page with `wcag2a`, `wcag2aa`, `wcag21aa`, `best-practice`; in-page timing probes for drag, mode switch and search keystrokes |
| Build        | `pnpm --filter @smarthome/home-docs build` for asset sizes                                                                                                |
| Not verified | Screen-reader output (NVDA/VoiceOver), real touch devices, Firefox/WebKit, production-build frame timing, users with vestibular or low-vision needs       |

Timing numbers were measured in the **development** build with React Strict Mode;
they show relative cost and per-frame structure, not production latency. Treat
them as indicative until a production benchmark exists (see P-01).

Severity scale: **High** blocks or misleads a class of users; **Medium** degrades
a common task; **Low** is polish or a missed opportunity.

## Things that already work well

Recorded so future changes do not regress them.

- Escape order for viewer, view options, and isolation matches the visual stack.
- Search supports arrow keys, Enter, Escape-to-clear, and scrolls the active option into view.
- Explode/stack uses a proper eased tween; hover preview is mouse-only so touch taps are not lost.
- Theme is applied before first paint from `localStorage`, avoiding a flash.
- The `prefers-reduced-motion` rule exists, and `floatIn` durations are short.
- Wheel zoom uses a non-passive listener so the page does not scroll behind the model.
- axe reports only two violations at the DOM level; most gaps are semantic and interaction-level, which axe cannot see.

## Recommended order of work

1. **Keyboard and semantics (A-01, A-02, A-03, A-06, A-07, A-08)** — largest class of excluded users; mostly additive markup.
2. **Type scale and contrast tokens (A-04, A-05, V-03)** — one token pass fixes many readability items at once.
3. **Render split and memoisation (P-02, P-03, P-04, P-05)** — required before adding more motion (M-01–M-03), or every animation will fight the full-tree re-render.
4. **Mobile layout (L-01, L-02, L-04, L-05, L-06)** — the narrow layout currently hides the product's centrepiece.
5. **URL state and hover states (U-01, U-02)** — highest QoL return for the least design risk.
6. Motion vocabulary and polish (M-_, V-_) once the above land.
